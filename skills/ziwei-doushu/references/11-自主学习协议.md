# 自主学习协议（模型迭代的规矩）

目标：让模型能持续吸收新资料、新案例，又不被个案牵着走。核心不是「学得多」，而是**学得可回滚、可证伪**。

## 一、可用的学习材料

| 类别 | 来源 | 现状 |
| --- | --- | --- |
| 原典 | 集文书局《紫微斗数全书》影印（竖排，OCR 不可靠，需逐页读图） | 已取亮度表、22 星逐宫条 |
| 讲义 | 倪海厦《天纪》视频同步稿上/下册（458 页，OCR 可用） | 已取框架、应期口径 |
| 课程 | 黑白书院《紫微斗数进阶·命相与阳宅同参》270 页 | 已取星曜落宫表、十二神、同参规则 |
| 公开项目 | iztro（排盘口径）、Renhuai123（天纪体系）、MingLi-Bench（32 盘＋160 题） | 已做 32 盘对照 |
| 真值 | 用户提供的已发生事件（含年份，最好含月份） | 14 例 |

## 二、每轮迭代的固定流程

1. **提假设**：写成一条可判定的话（「X 条件成立时，Y 类事件在某年发生」），进 `logs/hypotheses.md`，状态 pending。
2. **定判据**：写成代码可执行的形式，**先冻结**，记录在假设条目里。
3. **跑留出检验**：按人划分 + 时间外推；样本 <20 的类别只记录不调权重。
4. **判决**：
   - 留出集提升且不拖累其他例 → 并入评分，changelog 记 rN，打 tag；
   - 无提升或拖累 → 回滚，假设标 rejected，写原因；
   - 只有样本内提升 → 标 in-sample-only，**不得**写进结论。
5. **复盘**：每 5 次改动或每月，检查一次失败记录与口径漂移。

## 三、防拟合硬规矩

1. 一个类别的事件样本 <20 例时，只允许**修 bug 与口径**，不允许调权重；
2. 每次只用「设计时未看过」的年份做验证（时间外推优先）；
3. 同一事件不得既用于设计又用于报分；
4. 多假设并行时，用 FDR 或预注册顺序控制；
5. 任何「两头都说」的断语（强时如何、弱时如何）必须改为条件式，否则不得入库。

## 四、我能自主做的与不能做的

**能**：
- 从已 OCR 的资料里抽取规则、做结构化入库与去重；
- 重构代码、补边界测试、跑基准、写文档、维护版本与回滚点；
- 在你给出新事件后，按上面流程跑一轮并给判决。

**不能**：
- 无法自行获得「真值」——没有你的事件数据，任何「优化」都只是自说自话；
- 不能训练模型权重，所谓学习＝规则扩充＋权重校准；
- 不能替你判断流派取舍（庚干科取天府还是太阴这类），这属于口径决定，必须你点头；
- 不能凭影印本猜字，看不清就标注「待核」。

## 五、节奏建议

- **每收到一批新事件（≥3 例）→ 跑一轮**，产出：判决表 + 版本号 + 回滚点；
- **每两轮 → 打一个 tag**，并更新 `references/04` 的失败记录；
- **每季度 → 做一次口径复核**（夏令时表、四化表、亮度表是否仍与选定底本一致）。
